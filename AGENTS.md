## Project rules
- OctoOdds is an analytics tool, not a bookmaker: no page takes, holds or pays out bets. Keep copy and metadata (`__root.tsx`, route `head`s) free of sportsbook/casino/bonus wording — payment providers review the live site. The old sportsbook demo (bet slip, events board, promo banner) was removed.
- `/` is the public landing page (`src/routes/index.tsx`) built on `src/components/ui/hero-financial.tsx`, adapted from 21st.dev with dependency-free helpers in `src/components/ui/hero-financial-utils/` (CSS/IntersectionObserver entrance, shadcn Sheet drawer). Its button is "Log in" → `/login` for visitors and "Open app" → `/calculator` once signed in.
- `/sample` is public on purpose (no `ProtectedRoute`): a read-only tour for visitors and unpaid accounts. Its figures come from `src/lib/sample-showcase.ts` (tests beside it), which only composes the real calculator/scanner math with made-up inputs — fixtures from `src/lib/sample-data.ts`, demo prices from `odds-feed.ts`, bets from `src/lib/sample-bets.ts`. Nothing on it is editable or saved, and time-dependent sections are computed after mount to keep SSR and hydration identical. The unpaid "Subscription required" notice links to it.
- Cover calculator math (scenarios, tax-aware payouts, Balance / Balance win / Turbo / give-up plans, exposure) lives in `src/lib/calculator.ts` with tests beside it; the page only calls it.
- Calculator plans are stored in the shared OctoOdds Supabase `bets` table via `src/lib/plans-db.ts` (fetch/insert/update/delete). `src/lib/plan-mapping.ts` converts SavedPlan ↔ bet row using OctoOdds' conventions (row names "AW + BL", tax as a rate, won_scenario name or "__LOST__") and has tests beside it. `/calculator` is gated by `ProtectedRoute` (`src/components/auth/ProtectedRoute.tsx`). My Bets and Stats read the same table; settling/resetting writes `won_scenario`, `settled_at` and corrected `rows` via `savePlanResult`. Sample bets (`src/lib/sample-bets.ts`) are only shown on the read-only `/sample` page. `/admin` (admins only, `ProtectedRoute requireAdmin`) ports OctoOdds' member management: grant/revoke plans, roles, and the `app_settings.paywall_enabled` switch — all shared with OctoOdds.
- Scanner odds are live from The Odds API, ported from OctoOdds: `src/lib/live-odds.ts` (client types, `toFeedGames` converter, server functions) and `src/lib/odds-server.ts` (server-only: `ODDS_API_KEY` from `.env.local`, never `VITE_`-prefixed; shared 3-minute cache with in-flight coalescing; `assertApprovedUser` so only signed-in paid accounts can spend credits). Live fixtures are converted to the `odds-feed.ts` `Game` shape so the scanner/edge math is unchanged; `odds-feed.ts`'s deterministic generator is now only the Demo source. 1xBet is `1xbet` here and `onexbet` in the API (`apiBookKey`/`feedBookId`). `/scanner` is gated by `ProtectedRoute`.
- Scanner/Edge math (dutching combos, full covers, safest exclusion, arbs, EV, margins) lives in `src/lib/scanner.ts` and `src/lib/edge.ts` with tests beside them; pages only call them.
- Scanner settings and the last scan persist in the browser via `src/lib/scanner-store.ts`; Edge reads the same scan from there. Combos reach the Calculator through the one-shot handoff in `src/lib/calculator-plans.ts`.
- Bet results (pending/won/lost/break-even), settling, and all Stats figures live in `src/lib/bets.ts` with tests beside it; status is always derived via `outcomeOf(computeBet(bet))`, never stored, so My Bets, Stats and the Calculator can't disagree.
- Auth uses the same Supabase project as OctoOdds (accounts/profiles are shared). The client lives in `src/lib/supabase.ts`, session/profile/paywall state in `src/lib/auth.tsx` (`AuthProvider` wraps the app in `__root.tsx`). Credentials come from `.env.local` (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, gitignored). `/login` is the OctoOdds sliding sign-in/sign-up card restyled in this app's palette (`src/components/auth/AuthSwitch.tsx`).
- My Bets opens a plan in the Calculator through the one-shot `openInCalculator` key in `src/lib/calculator-plans.ts`.
- Verify with `npx tsc --noEmit`, `npx vitest run`, `npx eslint <changed files>` (prettier runs through eslint) and `npm run build`. Adding a route file needs the router plugin to regenerate `src/routeTree.gen.ts` (the dev server or `npm run build` does it) before `tsc` passes.
